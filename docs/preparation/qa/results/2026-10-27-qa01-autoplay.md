## 결함: 다중 모니터에서 포크 전체 화면 전환 실패 → 크래시

1차에서 포크가 15/17판에서 `0xC0000005`로 죽었다. 원인 사슬은 다음과 같다.

1. 창 위치에 따라 성패가 갈렸다. 첫 창이 주모니터 `(1578,767)`에 생긴 2판은 성공했고, 아래 모니터 `(1578,2927)`에 생긴 15판은 모두 실패했다(17판 전부 일치).
2. 실패 판의 로그: `画面解像度を 3840 x 2160 … に変更します` → `Direct3DDevice9 の作成に失敗しました` 4회(DxLib 재시도 경로 전체) → `予期せぬ画面モード変更不能現象が起きました2`. DxLib이 `-1`을 돌려주고 그래픽 시스템은 초기화되지 않은 상태로 남는다(`dep/DxLib/DxGraphics.cpp` 28484-28523행).
3. 포크의 `ApplyScreenMode`(`LR2/Main.cpp:190-225`)는 `ChangeWindowMode(0)`의 반환값을 확인하지 않는다. 장치 없이 진행한다.
4. `BMSの画像とサウンドをロードします` 직후 `DxLib::DrawMemImg`(`dep/DxLib/DxMemImgDrawFunction0.cpp:299`)에서 접근 위반이 난다. WER 이벤트 4건 모두 오프셋 `0x3c0407`이고, 같은 빌드의 PDB로 함수와 줄을 확인했다.

대조 실험: 주모니터 1대만 켠 3차(전체 화면)에서는 17판 모두 D3D 실패 0이고 크래시가 없었다.

**미확정 원인(가설)**: 포크의 `GetUseDisplayIndex`는 모니터 번호를 "주모니터 = 0" 체계로 바꿔 `SetUseDisplayIndex`에 넘긴다. DxLib은 이 값을 D3D9 어댑터 번호로 쓰면서(`Windows/DxGraphicsD3D9.cpp:5887,6565`), 전체 화면 해상도는 같은 값으로 `EnumDisplayMonitors` 순서 배열 `DisplayInfo[]`에서 가져온다(`DxGraphics.cpp:27792`). 두 순서가 다르면 다른 어댑터에 다른 모니터 해상도를 요청한다.
D3D9 어댑터 순서를 [windows/d3d9probe.cpp](../windows/d3d9probe.cpp)로 모니터 3대 상태의 대화형 세션에서 찍어야 확정된다. 아직 실행하지 않았다.

수정 방향(미착수): (a) 모니터와 어댑터를 `GetAdapterMonitor`/장치 이름으로 대응시켜 번호를 고른다. (b) `ChangeWindowMode` 실패 시 창 모드로 되돌리고 진단을 남긴다. (b)만으로는 크래시만 사라지고 비주모니터 전체 화면은 여전히 안 된다.

## 그 밖의 관찰

- **DPI**: 창 모드에서 원본 창은 990×785, 포크 창은 662×536이다. 포크의 DxLib은 `SetProcessDpiAwareness(SYSTEM_DPI_AWARE)`를 호출해(`dep/DxLib/Windows/DxWinAPI.h:52-68`) 150% 배율에서 확대되지 않는다. 원본(DxLib 3.01a)은 DPI 비인식이라 Windows가 비트맵 확대한다. UHD-01 입력.
- **로그**: 원본은 `outputlog=1`이어도 `DxLib_Init` 이전 메시지(설정 로드·스코어 해시)를 남기지 않는다. 포크는 `outputlog=0`이어도 `Log.txt`를 쓴다. 비교는 DxLib 초기화 이후 줄만 가능하다.
- **코드 페이지 949**: 직접 플레이 경로의 일본어(`日本語 曲名 テスト`)·한국어 폴더가 두 엔진 모두 로드·완주됐다. 일본어 문자가 CP949에 들어 있어 이 경로는 표현 가능했다. 일본어 로케일(932)에서의 결과와 같다고 보지 않는다.

## 검증하지 않은 것

- 판정 폭·게이지·리플레이: 자동 플레이(전부 PG)라 비교 대상이 아니다. 실제 입력 또는 리플레이 재생 비교가 필요하다.
- 키음: `7key_base62`의 `0a`/`0A` 구분, 비ASCII 파일명 키음(`鍵音02.wav`, `건반02.wav`), `case_mismatch` 재생 여부는 소리로 확인해야 한다. 스크린샷으로는 알 수 없다.
- 선곡 화면: 곡 목록 표시, 제목 깨짐(UTF-8/CP932), `broken/` 목록 등록. 직접 플레이는 선곡 화면을 거치지 않는다.
- 결과 화면: 직접 플레이는 플레이 후 곧 종료돼 결과 화면 사진이 없다.
- 캡처 누락 5칸: 1차 원본 `base62`·`ja_cp932`는 마지막 사진이 페이드아웃 검은 화면이다. 2차 포크 `base62`·`lnobj`·`scroll`은 다른 창(브라우저)이 게임 창을 가렸다. 실행기는 화면 영역을 복사하므로 가려진 창을 찍지 못한다. 다음 실행 전에 `PrintWindow(PW_RENDERFULLCONTENT)` 또는 전경 전환을 넣어야 한다.
- 다중 모니터 결함의 어댑터 순서 가설.
